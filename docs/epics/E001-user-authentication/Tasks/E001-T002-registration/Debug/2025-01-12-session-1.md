## Problem
Registration form accepting emails like "test@" and "user@domain" (no TLD).

## Hypotheses
1. ❌ Zod schema too permissive
2. ✅ Client validation running but server validation missing
3. ❌ Validation error not displayed to user

## Investigation

### Hypothesis 1: Zod schema
```typescript
// Checked src/lib/validations/auth.ts
// Schema looks correct:
email: z.string().email()
```
❌ Schema is correct, not the issue.

### Hypothesis 2: Server validation missing
```typescript
// Added debug logs:
console.log('[DEBUG_TRACE]', 'register', { email, validationResult });

// Output showed:
// [DEBUG_TRACE] register { email: 'test@', validationResult: undefined }
```
✅ **Found it!** Server endpoint not calling validation before insert.

## Root Cause
`src/app/api/auth/register/route.ts` line 15 — missing `schema.parse(body)` call.

## Fix
```typescript
// Added validation before processing:
const validated = registerSchema.parse(body);
const { email, password, name } = validated;
```
